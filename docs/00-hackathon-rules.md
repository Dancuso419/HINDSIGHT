# Hackathon Rules — Non-Negotiables

Source: https://bitget-ai.gitbook.io/bitgetai_hackathons2
Landing page: https://www.bitget.com/activity-hub/hackathon

> The handbook contains internal date contradictions (voting listed as both 9/22–10/7
> and 9/24–9/29; deadline listed as both 9/21 and 9/23 in one FAQ). **Treat 9/21 as the
> deadline.** Re-check the live handbook before submitting.

---

## An entry is INVALID (not scored at all) if it is missing any of:

1. **Project description** — written in full inside the Google Form field.
   A GitHub README or an X thread **cannot substitute**. This is the most common
   disqualifier for developers.
2. **Submission materials link** — an accessible demo. If a stranger cannot open it,
   it does not count.
3. **Compliant X post link** — must include `#BitgetHackathon` and `@Bitget_AI`, and
   must substantively describe the product being built. A bare retweet is not enough.
4. **Track + sub-theme selection.**

Incomplete answers on user/validation sections do **not** invalidate — they lower score.

---

## Project description: 6 parts, one field

Judges weigh **parts 1–3 most heavily**.

| Part | Requirement |
|---|---|
| 1. Thesis | Why built, core hypothesis, pain point, why existing tools fall short |
| 2. Target user & product value | **A concrete segment. "All traders" is explicitly rejected.** Include risk appetite, capital size, trading frequency, market, use case |
| 3. Validation data & key metrics | Tools: test users, task completion rate, usage data. Label every figure `observed` / `estimated` / `target`. No data yet → describe the validation plan |
| 4. Progress | Built vs not built, problems hit, fixes, next steps, frameworks/models/APIs |
| 5. Deliverables | Index of what is in the materials link so judges can find things |
| 6. Take on AI trading | Optional |

Separate mandatory field: **"Role of the LLM in Your Project"** — which models, doing what
(coding, extraction, signal reasoning, agent decisions).

---

## AI Trading Desk track — required materials

- Accessible demo — **required**
- One complete research task demonstrated end to end (question → actionable insight) — **required**
- Compliant X post — **required**
- Optional but recommended: screen recording

**Scoring: 100% subjective judge scoring.** Judging focus is feature depth (number and
effectiveness of data sources / Skill integrations), research quality, LUI fluency,
personalised thesis.

Implication: there is no metric to hide behind. Polish, coherence and a believable user
story are the whole game.

## Two-entry rules

- Max **2 themes** per team. No stated limit on tracks.
- Each entry = **independent project + independent materials + separate form submission**.
- **Keep the same Bitget UID across both.**
- Entries are judged separately and awarded separately.
- Shared UI shell / LLM wrapper is fine. Two repos that are the same app renamed is not.

---

## Prize exclusivity (matters for strategy)

- Judge side, same entry: only highest tier counts — Grand > Theme/Open > Best Spread.
- **University Special Prize is mutually exclusive with main-track prizes** — but applies
  **per entry**. Entry A winning a Theme Prize does not block Entry B from the university pool.
- Fan Favorite (public vote) stacks with everything.
- 10 university winners × 500 USDT, judged in a separate pool. **Requires the "University
  Name" field to be filled in.** Blank = not evaluated. This is the single best-odds prize.
